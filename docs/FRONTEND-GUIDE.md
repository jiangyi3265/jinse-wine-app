# 金色酒业微信小程序前端 V3

基于已确认的 V3 画板及 V2 补充页面，用 uni-app + Vue 3 实现的28个可运行页面。支持 H5 浏览器预览和微信小程序构建。

## 运行

```powershell
cd "path/to/jinse-wine-app"
npm install
npm run dev:h5
```

浏览器访问 `http://127.0.0.1:5173/`。手机宽度390px为主要设计基准，桌面浏览时内容居中展示。

```powershell
npm run build:h5
npm run build:mp-weixin
npm test
```

- H5生产目录：`unpackage/dist/build/h5`，需由静态Web服务器提供，不要直接双击index.html。
- 微信小程序目录：`unpackage/dist/build/mp-weixin`。在微信开发者工具中导入此目录，小程序AppID使用 `manifest.json` 中的配置。
- HBuilderX也可以打开本项目；当前使用Vue 3模式。
- 已用本机Node.js 24验证，所有DCloud依赖锁定同一版本，升级时请保持版本一致。

uni-app构建通过后，优先使用微信开发者工具自带的 `wcsc.exe` 检查WXSS。未安装开发者工具时，检查脚本会对生成文件执行静态语法和浏览器专属选择器检查，并在输出中标注 `static`；这不能替代官方编译器，但可以保持本地验收可复现。PowerShell示例（将路径换成实际安装位置）：

```powershell
$env:WCSC_PATH = 'D:\微信开发者工具\resources\app.asar.unpacked\node_modules\wcc-exec\wcsc.exe'
npm run check:wxss
# HBuilderX运行时生成的目录也可单独检查
npm run check:wxss -- unpackage/dist/dev/mp-weixin
```

浏览器专用样式放在 `/* #ifdef H5 */` 条件编译区间内，避免将WXSS不支持的通配选择器编入小程序。

## 页面与流程

| 模块 | 页面 |
| --- | --- |
| 商城 | 首页、商城、商品详情、确认订单 |
| 优惠活动 | 领券中心、我的优惠券、积分兑换、中秋活动 |
| 抽奖兑奖 | 扫码有礼、现金红包、我的奖品、兑奖网点、门店二维码 |
| 会员 | 我的、个人资料、VIP社群、我的订单、订单详情、收货地址、编辑地址 |
| 推广与服务 | 推广中心、推广海报、销冠排行榜、我的团队、门店核销、记录、在线客服、规则说明 |

- 底部：首页 / 商城 / 扫码 / 推广 / 我的。
- 购物：商品详情选择数量 → 购物车/结算选择优惠券与地址 → 服务端报价 → 创建待付款订单 → 查询真实支付状态 → 查看履约与售后状态。
- 领券：按渠道筛选 → 领取 → 我的优惠券；结算页选择可用券，也可不使用券。
- 积分：选择券或实物 → 确认兑换 → 同步扣减积分与库存 → 在优惠券或奖品中查看。
- 抽奖：H5可预览现金、积分、券和实物四类奖励；微信端提供扫码入口和演示入口。
- 核销：可选取演示奖品或输入演示码 → 核对 → 确认；同一奖品不能重复核销。
- 海报：可选择上架商品，Canvas 按原图比例绘制并保留价格分位，在 H5 下载 PNG 或复制带邀请码的商品链接；微信端保存相册并使用原生分享。邀请码未获取时禁用推广操作，只有二维码缺失时仍可分享链接，并提供重新获取入口。海报码和分享链接均直达所选商品并携带推广身份；切换商品时旧码立即失效，须等新码就绪后才能保存海报。绘制源文件为 `services/poster.js`，页面源文件为 `pages/poster/index.vue`。

## 演示边界

本地联调包通过 `bin/start-local.ps1` 注入 `VITE_MINI_MODE=api`、`VITE_MINI_API_BASE_URL=/dev-api` 和 `VITE_MINI_DEV_CODE=local-dev`，商品、门店、会员、积分、订单、奖品、优惠券、抽奖和核销数据均从后端读取。单独运行 Node 单测时才自动使用 `demo` 模式；离线预览可显式设置 `VITE_MINI_MODE=demo`。

库存、优惠券锁定/释放、订单幂等、抽奖概率与库存、核销范围、积分流水和推广佣金由服务端完成。微信支付、商户转账、退款、官方小程序码、企业微信群和视频号/微信小店需要正式平台凭据、权限及公网 HTTPS 回调；未配置时页面显示明确的处理中或配置错误状态，不伪造成功。

- 演示模式的二维码明确标为“示意”；API 模式缺少正式二维码时显示“二维码未配置”，不加载本地示意码，也不可实际进群或兑奖；正式活动码由服务端生成并记录。
- 公众号、视频号、电话、门店坐标没有正式配置时会给出明确反馈，不跳转到虚构账号或号码。
- 视频号打开回调不作为关注成功或自动发券依据。
- 推广佣金、排行和团队由服务端按订单履约、核销和结算状态计算；提现仍需财务审核和实际转账回执。
- 角色和门店范围由服务端校验，前端只负责展示可用入口。
- 持久化键名：`jinse-frontend-v3-state-1`。清除此项即可恢复初始演示数据，不需要清除其他项目的存储。

## 核心代码

- `pages/`：28个页面，均为原生uni-app组件实现，图片仅作为商品摄影等素材。
- `components/`：导航、安全区、底部导航、价格、券卡、二维码及空状态。
- `styles/app.css`：画板色彩、字体、间距及320/390/430px适配。
- `services/catalog.js`：商品、券模板、积分奖品、门店及排行示例数据。
- `services/pricing.js`：以整数“分”为单位计算价格、门槛、折扣、范围与上限。
- `services/store.js`：本地演示状态、权益记录与重复操作保护。
- `tests/`：19项金额、权益及订单状态测试。

设计图片中的参考价格、名称与摄影均为示例。正式上线应替换为实际商品、参考价依据、活动规则及品牌素材。

## 素材来源

摄影主要提取自项目中用户确认的V2/V3设计稿，仅提取摄影区域，页面文字、价格和操作控件全部重新开发。

`static/design/detail-scene-clean.jpg` 使用内置ImageGen清理了原画板照片中固化的轮播计数，随后等比缩小压缩；生成说明及完整提示词见 `ASSET-PROMPT.md`。其余线性图标由 `scripts/icons.mjs` 确定性生成。没有调用付费图像API。

## 验证结果

本次通过 H5 与微信小程序生产编译、19 项自动测试。浏览器已逐页检查 28 个路由，验证商城搜索筛选、优惠券报价、订单创建/取消、支付状态、积分兑换、红包状态、核销以及 PNG 海报导出。更多检查范围见 `QA.md`；正式支付、商户转账、真机扫码和平台渠道仍需凭据齐全后验收。

微信真机支付、到账、扫码活动和正式账号服务需要配置后台与AppID后另行联调。
